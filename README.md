# Agent Reliability

**Does fine-tuning a small model beat wrapping a bigger one in retry logic?**

A model that solves a task once is not reliable. This measures `pass^k` — the
fraction of tasks where **all k** independent attempts succeed — because that is
what "works" means when something depends on it.

---

## Result

Qwen3-1.7B, fine-tuned on 684 verified tool-use trajectories generated by
Qwen3-4B. Held-out 150 tasks, touched once. Two independent training runs.

| Metric | Base | Trained | Change |
| :-- | --: | --: | --: |
| Solves it once (`pass^1`) | 0.303 | **0.515–0.525** | **+0.21 to +0.22** |
| Solves it **4 times out of 4** (`pass^4`) | 0.247 | 0.393–0.413 | +0.15 to +0.17 |
| Solves it at least once in 4 (`pass@4`) | 0.353 | 0.627–0.680 | +0.27 to +0.33 |
| Tokens generated per task | 45.9 | **35.8** | **0.78×** |

Paired against the same tasks: `pass^1` +0.222 [95% CI +0.155, +0.290] and
+0.212 [+0.143, +0.280] on the two runs.

**Cheaper and better.** The trained model uses about a fifth fewer tokens per
task while being 21 points more accurate. Capability moved into the weights is
not paid for again at inference.

---

## The finding that matters more than the headline

**Training widened the reliability gap it was supposed to close.**

The band of tasks solved *sometimes but not always* went from **0.107 to 0.287**.
The model now solves far more problems on some attempt, and repeating that
reliably lagged well behind.

Quoting `pass@4` would let you claim +33 points. The number where every attempt
has to hold is +15. That difference is the whole point of the project.

---

## Two things the measurements ruled out

**It did not get better at maths.** Probed with no calculator at all: 64.0%
before, 66.0% after. Barely moved. What improved is writing the *right
calculator expression*, not arithmetic.

**It did not learn to cheat.** A model can solve a problem in its head and hand
the answer to the calculator, scoring correct having computed nothing. Measured
under a filter that catches the decorated form (`391 + 0` computes nothing but
parses as arithmetic): **3.0% before, 1.0% after**. It fell.

---

## What is honestly still missing

- **This does not answer the headline question.** That needs an 8B scaffolded
  comparator, which is registered and has never been run.
- **The teacher was Qwen3-4B**, not the larger model originally planned, so only
  the smaller model was trained. Nothing here speaks to the 4B.
- **Two training runs is a range, not a variance estimate.** No interval on the
  effect size itself is claimed.
- The untrained model emitted **four identical answers on 82 of 150 tasks**, so
  its `pass^4` partly collapses to `pass^1`. Restricting to tasks where both
  arms genuinely varied, the gap *widens* to +0.215 — the finding survives, but
  the caveat is real.

## How it is kept honest

Accuracy comes from executing the tool and reading the result, never from
reading the model's prose. Every result file is frozen by SHA-256 in
[`results/artifact_manifest.json`](results/artifact_manifest.json), so a
measurement cannot be edited after the fact without failing a test. Training
and test tasks are disjoint by ID and by content hash. The checkpoint was chosen
on a dev split by a rule written down before any dev number existed.

```bash
python -m unittest discover -s tests
```

Reasoning behind each choice, including the ones that went badly, is in
[`DECISIONS.md`](DECISIONS.md).
